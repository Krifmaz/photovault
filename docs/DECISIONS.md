# Decisions

One line per non-obvious call, newest last.

- 2026-11-04: Backup progress notification (Photos app): the app is Flutter, so Krifmaz/kit's kit-compose (Jetpack Compose) widgets cannot render in it and linking the library would put kit's AGP/Kotlin/Compose pins into Flutter's Gradle build; the banner and copyable error details are Flutter widgets that follow kit's rules (plain words, errors copyable), and no kit piece was added because no app would use it yet. Photovault Native (Compose) is the place to use kit's notices/toasts if it gets the same feature.
- 2026-11-04: Backup notification runs the app as a `dataSync` foreground service only while uploading; paused, failed and finished states are plain notifications, so no wake lock is held and Android 15's daily `dataSync` budget is not spent while waiting.
- 2026-11-04: "Backup complete: N photos" says photos for any file type (as asked); videos count too.
- 2026-11-04: Android release versions come from the tag: versionName is the tag without the `v`, versionCode is `major*1000000 + minor*10000 + patch` (set by `release.yml`; rises every release with no stored counter and sits above Ente's 2158). Limits minor < 100, patch < 10000; the version job fails past them. `--split-per-abi` makes Flutter add 2000 to the arm64 APK's code (v0.1.5 ships as 12005), a constant offset.
- 2026-11-04: A release build without the `PHOTOVAULT_KEYSTORE_*` secrets fails instead of shipping a debug-signed APK, and the certificate is checked against the Photovault key's SHA-256; PR and push builds still fall back to the debug key so CI runs without secrets.
- 2026-11-04: Photos APK native libraries are compressed (`useLegacyPackaging = true`): the APK is downloaded from GitHub Releases, so download size (218 MiB to 74 MiB together with arm64-only splits) beats the extra install space for extracted libraries.
- 2026-11-04: Photos APK is arm64 only (`--split-per-abi`, `--target-platform android-arm64`): CI builds the Rust library only for `aarch64-linux-android`, so an armeabi-v7a APK could not run anyway. Dart debug info is split out (`--split-debug-info`, uploaded as an artifact); `--obfuscate` is off because some code prints `runtimeType` names.
- 2026-11-04: Storage card shows the disk, not "used + free": total/used/available come from `statvfs` counted like `df` (used = `f_blocks - f_bfree`, fill = used / (used + avail)), so the numbers match what an admin sees on the host. Ente's `subscription.storage` becomes the disk's size (or the quota), while `usage` stays the account's bytes because the stock apps use it for per-account and family figures; the disk-wide "used" and the 90% warning come only from `/photovault/usage` (`disk`, `userBytes`), which the Photos app and web card read. Units stay 1024-based labelled GB/TB like `df -h` and the rest of the app.
- 2026-11-04: Photovault Native has no storage card yet (its `storageUsage()` has no UI), so this change leaves it alone; `disk`/`userBytes` are additive in the contract for when it gets one.
- 2026-11-05: Personal addresses scrubbed: examples use `photos.example.com` and `192.168.1.10`. App/web/server examples use port 8080 (the server's own port); deploy files and deployment docs use `http://192.168.1.10:8095` because they publish `"8095:8080"` and the example must match the host port. Port mappings are unchanged, so a stack deployed straight from `deploy/compose*.yaml` keeps its port but must set its real `PHOTOVAULT_PUBLIC_URL`/`PHOTOVAULT_HOME_URL`. The author email in past commit metadata stays: removing it would mean rewriting main's history.
- 2026-11-05: Photovault Native recent servers are stored in their own `server_seen` table (core store schema step 3) instead of new `servers` columns or fields in the ServerInfo JSON, so older stores load unchanged and the step can safely run again; `remove_server` deletes the row, sign-out keeps it.
- 2026-11-05: Core's address choice (`refresh_network`, also run by `select_server`) is: last address that answered, then home URL, then public URL. The last address and home are used only if they answer `/photovault/info` within 1.5 s with the same publicUrl; home stays ahead of public as `contracts/server-info.md` requires.
- 2026-11-05: A plain-http last address (e.g. `http://100.101.102.103:8080`) needs the same per-server approval as a plain-http home URL (`set_home_url_allowed`), because carrier CGNAT reuses 100.64.0.0/10; https addresses (a tailnet `*.ts.net` name) need none.
- 2026-11-05: The Tailscale probe runs in the Native app (ConnectViewModel, `fetch_server_info`, 3 s per address); core has no Tailscale-specific API. A server that answered only at its public URL while Tailscale is on is labelled "Reached at its public address", not "over Tailscale", because that traffic may not have gone through the VPN.
- 2026-11-05: Photos app recent servers are stored in a new SharedPreferences key `photovault.recent` (normalised public URL -> {connectedAt ms, address}); the saved list and `photovault.reachedAt` are kept as they were, and servers without a time sort after the timed ones (the active one first, then the stored order), so older data needs no migration step.
- 2026-11-05: Tailscale counts as active when any interface has an address in 100.64.0.0/10 or fd7a:115c:a1e0::/48; carrier-grade NAT on cellular can also use 100.64/10, and that false positive only costs a few short probes because every probe checks that the server reports the same public URL.
- 2026-11-05: Photos app, while Tailscale is up the address choice is home, then last address that answered, then public, then reachedAt; without the VPN it is unchanged. Tapping a recent server tries the last address first with a 3 s timeout so an old tailnet or LAN address doesn't hold up the public URL's normal attempt; if all fail, the error is about the public URL.
- 2026-11-05: Servers that answer a direct probe while Tailscale is up get their own "Found over Tailscale" section; "On this network" stays for mDNS results only.
